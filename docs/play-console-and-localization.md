# Localization and Android release follow-up

## Translation coverage

App-owned copy is maintained in `constants/Translations.ts` for English, Romanian, and Russian. The audit covers routes, components, dialog titles/buttons, input placeholders, schedule overrides, assignment editing, account deletion, developer tools, demo grades, notification channels, reminders, and digests. Existing PDF labels use the same catalogue. Official course names, teacher names, server-provided explanations, user-entered assignment content, language names in the language picker, and technical identifiers remain as supplied.

Date formatting uses the selected locale, including Russian month cases. Relative times and assignment counts use `Intl.RelativeTimeFormat` and `Intl.PluralRules`; Russian counts such as 1, 2, 5, 11, and 21 do not share one plural form. Notification text and Android channel labels are rebuilt after a language change. Notification setup waits for saved settings and serializes language changes.

Regression coverage includes:

- Catalogue key and interpolation parity, nonempty messages, calendar array lengths, balanced link markup, and untranslated English paragraphs.
- An AST scan of visible JSX text, input/accessibility labels, literal text fallbacks, and alert messages in every route and component. Standard 12-hour clock markers are allowed. This scan complements manual review of indirect text sources; it cannot prove translation quality.
- Live language switching, dates, relative times, plural forms, demo data, assignment reminders, and actual scheduled digest content.

Run `pnpm test`, `pnpm lint`, `pnpm typecheck`, and `pnpm format:check` after changing copy.

`expo-notifications` also contains a manual decoder in `notifications/presentation/builders/DownloadImage.kt`, and `expo-updates` contains one in `reloadscreen/ReloadScreenView.kt`. App-local assignment notifications have no image attachments, and the OTA reload flow does not configure a remote reload-screen image. Those library paths may still be reported by static analysis. Replacing or patching them requires native integration testing; the avatar migration does not claim to clear all bitmap warnings.

The reported obfuscated entries (`t52.K`, `z21.j`, `zp1.r`, `zp1.z`, and the bitmap entries) cannot be reliably attributed without the **matching release 17 mapping file**. Use its `mapping.txt` to retrace them before assigning each to an upstream library. A future build's mapping file cannot deobfuscate release 17 reliably. New mappings normally appear under `android/app/build/outputs/mapping/release/`.

## Build compatibility and release validation

The `expo-image` native module and Android build changes require a **new native build**. Version and EAS runtimes advance to 1.6.2 (`1.6.2-dev.1` and `1.6.2-beta.1` for the other profiles) so this JavaScript is not delivered into the older 1.6.1 runtime. Set the selected EAS environment's `RELEASE_VERSION` to the intended displayed release before publishing. No release is published by this change.

Generated Android configuration was inspected with `expo prebuild --platform android --no-install` in an isolated scratch project. It produced unrestricted orientation, `android.enableMinifyInReleaseBuilds=true`, `android.enableShrinkResourcesInReleaseBuilds=true`, and the JNI keep rule. An Android Metro export verifies JavaScript bundling; it does not compile or execute native image loading, R8, or window code.

Before releasing:

1. Build an AAB with the production EAS profile and retain its mapping file. Inspect the merged manifest and verify release resource shrinking actually runs.
2. Install a release build and check account images, cached/offline profiles, sign-in, notifications, PDF sharing, and Play in-app updates under R8.
3. On Android 15/16, rotate schedule/grades/settings/assignment forms, open the keyboard and sheets, and test gesture plus three-button navigation. On a tablet/foldable, repeat in split-screen and after resizing. Check Russian text for wrapping in narrow layouts.
4. Change app language and verify newly scheduled reminders and Android channel labels. Confirm official/user-entered content is preserved.
5. Upload the new AAB to a test track and inspect Play's new findings. Keep the edge-to-edge and dependency bitmap issues open until the new analysis confirms their status.
